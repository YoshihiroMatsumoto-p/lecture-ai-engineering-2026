# 第4回 宿題：ラベル確認用

比較用ラベルはAIが採点結果を見る前に作成した下書きです。本人による確認・修正はまだ行っていません。
質問・実際の回答・期待するふるまいを読み、各判定が妥当か確認してください。Tは合格、Fは不合格です。

# 実行条件

- 回答生成：第3回の `app.agent`、`gpt-4.1-mini-2025-04-14`。質問ごとに会話履歴をリセット。
- 採点：同じモデルの別の呼び出し。`data/eval/rubric.md`、temperature=0。
- 元のエージェントのInstructionsと採点基準は変更していません。
- 回答生成時のモデル名・日時・ツール呼び出し・トークン数は `data/eval/my_cases.jsonl` の `generation` に保存しています。
- この10件は動作と失敗例を見る小さな評価セットです。AIの仮ラベルとの一致率は、人による検証済みの精度を意味しません。

# 採点結果の確認ポイント

- 今回の一致率はAIの仮ラベルとの比較です。人の判定による校正はまだ済んでいません。
- 不一致は01の根拠、03の根拠、06のヒント・分かりやすさの4項目でした。LLMの採点理由は `my_judge_result.json` に保存しています。
- 01では、説明内容はおおむね正しい一方、関係する回を第1回とした点を仮ラベルで不合格にしました。この厳しさが妥当か確認してください。
- 03では、参照にHuman-in-the-loopがあるのに「用語集にない」とした回答を、採点LLMは合格にしています。
- 05では、未定義の「未知語を一般論で説明する」場合はunsureという基準があるのに、採点LLMはpassにしました。要確認0件という数値だけで、判断が明確だったとは言えません。
- 06では、コードをまだ提示していない点をLLMはヒントとして合格にしました。仮ラベルでは、保存内容を聞いてコード例を約束する返答は、課題の考え方を教えるヒントになっていないとして不合格にしました。
- `check_lecture_mark` は「最後の行に第N回が含まれるか」だけを調べます。06の確認文や10の第14回でも合格となり、回の意味・実在性は検証していません。一方、講座外への適切な拒否でも回の表示がなければ不合格です。
- 02と04はsearch_glossaryを呼ばず、get_lecture_summary / make_quizだけを呼びました。参照データを取得できていても、「必ずsearch_glossary」という手順を満たしたかは、回答だけの5基準では測れません。必要ならツール履歴をコードで検査する基準を追加します。
- 回答生成と採点には同じモデルを使っています。別の採点モデルや本人の判定と比べることは、今後の検証項目です。

# 再実行する場合

リポジトリ直下のターミナルで、`OPENAI_API_KEY` が設定されている状態で実行します。キーはファイルやGitに保存しません。

```bash
uv run python -m app.judge --generate --cases data/eval/my_cases.jsonl --model gpt-4.1-mini-2025-04-14
uv run --with streamlit==1.66.1 streamlit run tools/annotate.py
```

生成コマンドは回答を上書きします。今回の回答を確認するだけなら再生成は不要です。
Streamlitの評価セットを `data/eval/my_cases.jsonl`、ラベルの保存先を `lectures/04/my_labels.jsonl` に指定し、10件を本人が確認して保存します。

```bash
uv run python -m app.judge --cases data/eval/my_cases.jsonl --labels lectures/04/my_labels.jsonl --out lectures/04/my_judge_result.json --model gpt-4.1-mini-2025-04-14
```

ラベルを変更したら採点を再実行し、`answer.md` の数値を更新します。JSONを直接編集する場合、本人が確認した行だけ `human_reviewed` を `true` にします。
